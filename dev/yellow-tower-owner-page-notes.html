All notes, summary first, then in page order

  1. YELLOW TOWER OWNER PAGE (version 3, 2026-10-09, Page Claude Code, design desk; Kim 2026-10-09: "build the owner layer ... a separate page with
lots of info and ALL fields possible to enter, with a JSON kind of tree, expand and collapse"). Page 5 of the set, reached from the
top of the contact details page (page 4) when the security page said "I own or work here" (?role=owner or works_here).
Production route: kh34363.contact.page/owner after owner login (the "owner-pass"); noindex, never in the sitemap.

WHAT IT IS: one tree that mirrors CONTACT/schemas/master-listing.schema.json (v2.1) key by key, so the owner sees EVERY field the
schema holds (the nested leaves are the "88+"). Open or close any branch; "Expand all" / "Collapse all"; a search box; "Only empty" to
see what is missing; a progress bar "N of M filled". Owner layers (kb/data-pool-design-2026-10-06.md): 1 owner-pass = the "Register
record" branch, only here; 2 Refresh = the top button (about one day); 3 full-field view = the whole tree, with a hint per field;
4 "Try to find it" = on every empty field, with a warning and a box for the owner's own sources; 6 announcements, ownerFaq and
directions are branches; 7 "Show on my page" tick on every top-level branch, all ticked, unticked = hidden, never deleted
(schema hiddenSections). Layer 5 (portfolio) waits.

HOW A CHANGE IS SENT (rule: owners change things through our agent, README "Owner actions"): editing a box adds it to "Your changes";
"Send my changes" opens the owner's own email to the page code (ref owner) with one "key: value" line per change; our agents check
and apply. Under 1,700 characters per email (mailto limit). Production would save directly to the owner record, then agents check.

VISIBILITY TAGS: Public = shown on the page; Behind check = masked until the visitor passes the security check; Only you = never public
(taxID, registry, verification, provenance, licences); We fill = read-only for the owner (schemaVersion, portal, verifiedAt, nextCheckAt,
_verification, _provenance, _media_license). Contact lines are add-only (old ones archived with the date); profile fields are overwritten
(data-pool-design layer 6). No money data from scraping; prices only from the owner. No star ratings, no negative notes.

DATA: only what the other Yellow Tower mockups already show is prefilled (name, category, street, district, city, postal code, country,
phone, WhatsApp, page code). Everything else is empty on purpose; nothing is invented about Yellow Tower. The hints are examples only.
{{YT_PHONE}} is filled at publish (Yellow Tower is the only real business, N16).
