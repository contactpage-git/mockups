What changed and why (newest first)

Each step with the reason behind it: the lessons learned along the way. Open any version to see it as it was.

  • v8 2026-10-09 (Page Claude Code, from the architect session): the field order now mirrors x-priority in the schema (contact lines WhatsApp, email, website come before about and photos; all private fields, employees too, after the public ones). Owner or director (employees) is now tagged "Only you".
  • v7 2026-10-09 (Page Claude Code, Kim: "more like DRAFT and then a PUBLISH on top, subject to review"): the page is a draft. A sticky bar right under the title, above the boxes, shows DRAFT, how many changes are in it, and a Publish button (grey until there is a change); under it "Subject to review. Nothing goes live until we have checked it." Publish opens the owner's own email to the page code (ref owner) with the changes, then the bar says IN REVIEW, "Sent for review. We reply by email." The bottom "Send my changes" bar is gone. Visitor view: the same bar says "Send for review". Production: Publish saves the draft to the record and starts our review; same states.
  • v6 2026-10-09 (Page Claude Code, Kim: "too much text on top, square boxes again that expand for the info, e.g. a box for refresh"): the top is now just the title and three square boxes: Refresh, "12/105 filled" (live) and How it works. Tap a box and its few lines open under it; tap again to close. The subtitle, the Refresh card, the progress card and the tip line are gone from the top (same words, now inside the boxes). Visitor view keeps only the How it works box.
  • v5 2026-10-09 (Page Claude Code, Kim: "try to find it is not just us, we can send to Google AI or his AI and he copies and pastes back here"): "Try to find it" opens three ways. 1 Ask Google AI (AI Mode in a new tab with a short question about this business and this field, no contact values in it), 2 Copy a prompt for the owner's own AI, then paste the answer in the box and "Use this answer", which fills the field as an unsent change the owner can still edit; 3 Ask us (our agents research it, the owner can add sources). Private fields (Only you) get only "Ask us", never an outside AI. Nothing is saved until the owner presses Send.
  • v4 2026-10-09 (Page Claude Code, Kim: "by priority, top 5 on top, schema version and identifier at the end"): the list is in priority order. Top five: business name, main category, phone numbers, address, opening hours. Then about, photos, WhatsApp, email, website, logo, products and services ... then the owner-only private fields, then the fields we fill ourselves (page code, schema version, portal, verification dates). Three small grey captions mark the groups. The order is a first draft; the chief is asked to add a priority column to the schema.
  • v3 2026-10-09 (Page Claude Code, Kim: "ALL fields collapse and expand, just the readable name with an arrow, super clean long list"): every field, leaf or branch, is one closed row: arrow, readable name (not the schema key), a small dot when filled. Tapping the row opens it: visibility tag, the box, the hint, "Try to find it". Branch rows open to their children; "Show on my page" moved inside the branch. Tags, braces and counts left the closed rows. Removed from the closed row: the schema key, the visibility tag, the { } marks and the n/m counts (the top bar still counts).
  • v2 2026-10-09 (Page Claude Code, Kim): the same page with ?as=visitor is the community suggestion page: public fields only (no Only-you or We-fill branches, no Show-on-my-page ticks, no Refresh, no Try-to-find), suggestions go by email (ref suggest) and are checked before anything is published (only positive, true, useful facts, like Community notes). Why: the indexed listing page never shows Add holders (thin-page SEO), these holders live on noindex pages only.
  • v1 2026-10-09 (Page Claude Code, Kim): new page, tree of every schema field, layers 1-4, 6, 7, send-changes email.

All notes, summary first, then in page order

  1. YELLOW TOWER OWNER PAGE (version 8, 2026-10-09, Page Claude Code, design desk; Kim 2026-10-09: "build the owner layer ... a separate page with
lots of info and ALL fields possible to enter, with a JSON kind of tree, expand and collapse"). Page 5 of the set, reached from the
top of the contact details page (page 4) when the security page said "I own or work here" (?role=owner or works_here).
Production route: kh34363.contact.page/owner after owner login (the "owner-pass"); noindex, never in the sitemap.

WHAT IT IS: one tree that mirrors CONTACT/schemas/master-listing.schema.json (v2.1) key by key, so the owner sees EVERY field the
schema holds (the nested leaves are the "88+"). Open or close any branch; "Expand all" / "Collapse all"; a search box; "Only empty" to
see what is missing; a progress bar "N of M filled". Owner layers (kb/data-pool-design-2026-10-06.md): 1 owner-pass = the "Register
record" branch, only here; 2 Refresh = the top button (about one day); 3 full-field view = the whole tree, with a hint per field;
4 "Try to find it" = on every empty field, with a warning and a box for the owner's own sources; 6 announcements, ownerFaq and
directions are branches; 7 "Show on my page" tick on every top-level branch, all ticked, unticked = hidden, never deleted
(schema hiddenSections). Layer 5 (portfolio) waits.

HOW A CHANGE IS SENT (rule: owners change things through our agent, README "Owner actions"): editing a box adds it to "Your changes";
"Send my changes" opens the owner's own email to the page code (ref owner) with one "key: value" line per change; our agents check
and apply. Under 1,700 characters per email (mailto limit). Production would save directly to the owner record, then agents check.

VISIBILITY TAGS: Public = shown on the page; Behind check = masked until the visitor passes the security check; Only you = never public
(taxID, registry, verification, provenance, licences); We fill = read-only for the owner (schemaVersion, portal, verifiedAt, nextCheckAt,
_verification, _provenance, _media_license). Contact lines are add-only (old ones archived with the date); profile fields are overwritten
(data-pool-design layer 6). No money data from scraping; prices only from the owner. No star ratings, no negative notes.

DATA: only what the other Yellow Tower mockups already show is prefilled (name, category, street, district, city, postal code, country,
phone, WhatsApp, page code). Everything else is empty on purpose; nothing is invented about Yellow Tower. The hints are examples only.
{{YT_PHONE}} is filled at publish (Yellow Tower is the only real business, N16).
